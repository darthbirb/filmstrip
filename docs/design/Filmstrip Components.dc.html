Empty is six different facts, not oneA cleared Sorting Box, an emptied Trash, a folder of folders, a genuinely empty folder, a search that found nothing and a drive that is not plugged in are six different situations, and only the fourth is really "no pictures here". The shared shape is what keeps them from feeling like six designs; the words are what make them useful.
Only two of them offer an actionA folder of folders lists them as buttons, because going into one is the obvious next move and the counts are already known. A search that found nothing offers the wider search. The other four have nothing worth doing, and a button that only restates the situation is worse than no button.
A title is Title Case; a label is notThis card settled the titles by saying they take the same case the buttons use, and the button drawn under it read Add a folder…. Both cannot be right. The titles keep Title Case, because EmptyState.tsx ships Nothing Chosen Yet, No Pictures Here and Archive Is Offline — and every label on a button, in a menu row or in a tooltip is sentence case, which is what the pane's bar, the fold's tooltip and this sheet's own folder buttons already are. A title names a place; a label names something you are being asked to do. Two kinds of words, two cases, and neither borrows the other's.A line that is left keeps its full stop: it is a sentence. right-clickWhat is there instead of the browser's menuthree surfaces · one menu shape · pointer or keyboard
Yes, the app has a context menu, and it is Menu.tsx at the pointer — the same shape the pane's ⋯ already opens, 14rem wide with 2rem rows. It is on three things: a tile, a tree row, and the pane's picture. It never offers a verb the app does not already have somewhere else — for a file that somewhere is the pane’s action bar or its ⋯; for a folder or a source, where the bar cannot reach, it is the place that already holds the act: the walk the app runs at launch, and the Sources section of Settings. A right-click is a shortcut to what the interface can already do, so a verb living only here would be a verb nobody could find. The menu key and Shift+F10 open the same menus, against the focused tile or row instead of a pointer — with the browser's menu suppressed those two keys opened nothing at all. And the one row that had nowhere to happen, Rename on a tree row, happens on the row.

A folder is a thing the app can make, move and delete, so its row carries those three verbs beside the four it already had, in the menus' own order: the creating verb first, the acting verbs next, the destroying verb last and alone under a rule. None of the three opens a place of its own — New folder drops a row inside this one, already in the name field; Move to… opens the picker the bar opens for files; Delete asks only when the folder holds something. A source's row holds seven, in the same order: New folder, Favourite, then Reveal in Explorer, Rename, Read it again, then Manage sources… and Remove source. It is a folder's row without Move to… and without Delete, plus the two rows only a source has. New folder is on it because a source's row is the only row that stands for its own top level — without it nothing in the app could make a folder directly inside a source — and Favourite is on it because a source is a place like any other place in the tree. Three rows in this pair are not on the pane’s bar, and none of them is new, because the bar is about a file and these are about a place. Read it again is the walk the app already runs at launch, aimed at one folder. Manage sources… opens the Sources section of Settings, and Remove source is the red button on the row that section already draws — the menu points at both from the row they are about rather than holding anything of its own. A source has no Move to… and no Delete: a source sits inside nothing, so there is nowhere to move it to, and removing is what it has instead of deleting — it forgets a folder rather than touching it, which is why it is the only red row in navigation.

On a source's row · the app's own label, not the folder's name Archive
Enter renames, Escape cancels, and leaving the field renames — the same three keys the pane's Name row and the Sources section already answer to. A folder's rename is not built
Right-clicking never changes what is selected, except onceInside the selection it opens the set's menu and leaves the set alone. Outside it — on a tile with no check — it moves the selection to that tile first, so the menu is never about a file the pointer is not on. Windows behaves this way and the alternative is a Delete that acts on tiles you cannot see.
Where there is no menu, nothing opensThe grid's bare ground, a header, the window bar and the filmstrip's surround suppress the browser's menu and offer none of their own — an empty menu or a menu of one disabled row is worse than the click doing nothing. A filmstrip frame is a tile and gets the tile's menu.
A field keeps the platform's own text menuSearch, the rename field and the note field are the exception: suppressing the menu there takes away cut, copy, paste and the spell-checker, which the app does not reimplement. Everywhere else the native menu is the bug this entry is about.
The keyboard's menu hangs off the ring, and flips when it has toA pointer's menu opens at the pointer; a keyboard has no pointer, so the focused element is the anchor and the red ring is what says so. Below and left-aligned by default. With less room under the element than the menu is tall, it flips above it — the same 4px clear of the ring — and if it would leave the window either way it slides along the edge rather than shrinking. Escape closes it and the ring stays where it was, because closing a menu is not navigating.
Rename happens on the row, not in SettingsA tile's Rename goes to the pane's Name row and a source's goes to a field in Settings, so the tree's two Rename rows pointed at nothing. They take the third of the three shapes that already exist: the row becomes a field where it stands, which is what the Sources section does to a source's name. Sending a person to Settings to rename the row they are already on would be the menu pointing at a place instead of doing the act. A source's row edits the app's own label, the same string Settings edits, and nothing on disk. A folder's row edits the folder on disk, which is the one rename with no command behind it yet — hence the marker, and the clash state, which a label cannot have.
